## 2. Findings

Written by hand after the run, from these tables. Section numbers below refer to this document.

### 2.1 Verdict in one paragraph

reflop 0.4.5 passes all 697 cases that ran (683 pass, 14 xfail, 0 fail), the same cases as 0.4.4, and no case changed status. The 20 skips are a15, which needs the Guest to run on the Owner's hardware. The two changes 0.4.5 made both show up. LSTM and GRU steps take 1.6–3.2× less time when captured and 2.4–2.5× less eagerly, now that the fused cells are on by default (ADR-067). Opening a session takes 1.4 s instead of 3.5 s, and recovering from a lost worker takes 1.3–1.6 s instead of 3.4–3.7 s, because the runtime ships compiled bytecode (ADR-066). Without LSTM and GRU, step times changed by a median of −2.4 % (captured, resident) to −0.1 % (uploaded), within the spread between runs.

### 2.2 Confounders

1. **The network was the same.** Tailscale reported a direct LAN path both times. The b03 GPU RTT median was 4.076 ms, against 4.571 ms in OLD (−11 %). The link carried about 10.5 MiB/s in both runs.
2. **The GPU ran at the same speed overall.** Native CUDA took a median 0.4 % more time per step (§7.4), but the native CNN at batch 8 and 32 was 12–20 % faster in NEW. Compare overheads, not raw times.
3. **The client was this checkout, one commit after the v0.4.5 tag.** That commit only deletes a local tooling directory and changes no client or server code, so this run tests 0.4.5.
4. **Only two changes are on the execution path:** the fused LSTM and GRU cells on by default, and bytecode in the runtime, which changes only how fast a worker starts.
